## Session: 2026-06-05 - Plugin Install Deep Dive

### Root Cause Analysis
1. **No download URLs**: All 41 soft_catalog.json entries have NO `download` field in `versions[0]`. 
   - `install_sync()` checks `if 'download' in pluginInfo['versions'][0]` → FALSE
   - Falls to `__install_plugin()` → `__download_plugin()` which POSTs to `download.aapanel.com/api/panel/download_plugin`
   - API returns 400: "That plugin have not version [X.Y.Z]" — wrong version format

2. **Cache corruption**: Threshold `len(resp.text) > 100` too low. Fixed to `> 50000`.

3. **Two download paths**:
   - V1: `www.aapanel.com/api/plugin/download?filename={name}&token={token}` — needs `download` key + valid token
   - V2: POST `download.aapanel.com/api/panel/download_plugin` with `{name, version, os, environment_info}` — needs correct version format + auth

4. **Public data sources** (no download URLs):
   - `https://node.aapanel.com/install/list_pro.json` — 37 paid plugins (Chinese, versions as strings)
   - `https://node.aapanel.com/install/list_en.json` — 14 free plugins (versions as strings like "1.12,1.8,-Tengine2.2")
   - `https://node.aapanel.com/install/type.json` — type classification

5. **Install flow**:
   ```
   GET /plugin?action=get_soft_list → panelPlugin.get_soft_list() → get_cloud_list() → load_soft_list()
   POST /plugin?action=install_plugin → install_plugin() → get_soft_find() → install_sync()/install_async()
   ```

6. **async install**: `install_soft.sh <type> <install|update> <name> <version>` — downloads from `node.aapanel.com/install/{type}/{name}.sh` (public)

7. **PluginLoader.so**: Compiled binary that decrypts `plugin_bin.pl` cache. Can't patch directly. 
   - Attributes: db_decrypt, db_encrypt, get_auth_state, get_module, get_plugin_list, module_run, parse_plugin_list, plugin_run, py_clear
   - `get_plugin_list(0)` returns `{'status': False, 'msg': '...'}` for unlicensed panels

8. **BTPanel architecture**: Gevent WSGI server → Unix socket `/tmp/panel.sock` proxied by webserver (nginx-based) on port 23694

### Files Modified
- `class/public/common.py`: `_empty_soft_list()`, `_load_local_catalog()`, 6-point fallback in `load_soft_list()`, threshold 50000
- `data/soft_catalog.json`: 41 plugins (no download URLs)
- `custom_install.sh`: 9-layer patcher
- `test_subaccount.py`: 17 tests

## Session: 2026-06-05 — Plugin Manager Root Cause Analysis

### Debugging Method
Incremental patching on Pro activated panel:
1. Sentinel files only → OK
2. is_pro() → True → OK  
3. Lifetime patches → OK
4. Auth status → 200 → OK
5. JS bundles → OK (frontend only, can't break backend)
6. **load_soft_list catalog fallback → ROOT CAUSE**

### Root Cause
- Pro PluginLoader returns `f_path`/`f_md5` (NOT `download`) in versions
- Our catalog has neither
- `install_sync()` checks `'download' in versions[0]` → False → falls to `__install_plugin()`
- `__download_plugin()` V2 POSTs to `download.aapanel.com/api/panel/download_plugin` with version from catalog
- Cloud API rejects our catalog version numbers → PanelError → may not surface to UI
- On free panel, PluginLoader ALWAYS fails → catalog ALWAYS used → install ALWAYS fails

### Fix Applied
Gated all 4 catalog fallback points with `if not force:` guard:
- `force=True` → cloud API errors propagate → user sees error
- `force=False` → catalog used for display → plugin store works
- Install calls use `force=True` → if cloud fails, error shown naturally
- Display calls use `force=False` → catalog provides fallback list
